# 작업 재개 안내 — 한글화 파이프라인 사용법

체크포인트 3 기준. **추출 → 번역 → 폰트 → 재삽입 → 검증** 전 과정이 동작 확인되었습니다.

## 0. 준비

```bash
pip install pillow
apt-get install -y fonts-nanum        # 한글 16x16 비트맵 소스
# 업로드 ZIP 3개를 ext/ 아래 해제 → ext/files/ 에 683개 파일
```

## 1. 대사 추출 (이미 완료됨, 재실행 불필요)

```bash
python3 tools/dump_text.py ext/files tools/3x3eyes.tbl translation/script.jsonl
python3 tools/make_worksheet.py translation/script.jsonl \
        translation/script_ko.tsv translation/string_map.json
```

## 2. 번역 ← **지금 할 일**

`translation/script_ko.tsv` 의 **마지막 열(한국어)** 만 채웁니다.

| 열 | 뜻 |
|---|---|
| `id` | 문자열 ID (바꾸지 말 것) |
| `사용횟수` | 이 문자열이 게임 내 몇 곳에 들어가는지 |
| `바이트여유` | **번역문이 넘으면 안 되는 바이트 한도** |
| `일본어글자수` | 참고용 |
| `일본어` | 원문 |
| `한국어` | ← 여기에 작성 |

빈도순으로 정렬되어 있어 **위에서부터 번역할수록 효과가 큽니다.**

### 번역 규칙 (중요)

1. **제어코드는 원문 그대로 유지**합니다. 위치만 옮길 수 있습니다.
   - `<br />` 줄바꿈 · `<0xdb>` `<0xdb00>` 페이지 넘김 · `<return_p>` 다음 변형 대사
   - `<arrow>` `<speak>` `</speak>` `<portrait_NN>` `<wait_NN>` `<E7FC>` `<E7FD>`
   - `[player]` 주인공 이름 치환
2. `<return_p>` 로 구분된 덩어리는 **같은 상황의 말투 변형**(상인별 어투)입니다.
   각각 다른 어투로 옮기면 원작 느낌이 살아납니다.
3. 한 줄은 대략 **14~16자** 이내가 안전합니다(대사창 폭).
   길면 `<br />` 로 끊으세요. 한 화면은 4줄입니다.
4. `바이트여유` 를 넘으면 그 줄은 **보류되고 일본어가 남습니다.**
   `build_patch.py` 가 초과분을 전부 보고하니 줄여서 다시 돌리면 됩니다.
5. 한자·히라가나는 쓰지 마세요(한글 코드로 재배정되어 깨집니다).
   `¨` `♥` `～` 같은 기호는 자유롭게 써도 됩니다 — 글리프가 새로 생성됩니다.

### 소규모 배치로 작업하기

`translation/ko_batch01.tsv` 처럼 `ID<탭>한국어` 두 열짜리 파일을 만들어 두고
아래로 시트에 병합하면 작업 이력이 남아 좋습니다.

```bash
python3 tools/merge_batch.py translation/ko_batch01.tsv translation/script_ko.tsv
```

## 3. 패치 생성

```bash
python3 tools/build_patch.py ext/files translation/script_ko.tsv \
        translation/string_map.json build/files
```

하는 일:
1. 번역문에 쓰인 문자를 집계하고 **빈도순으로 코드 배정**
   - 빈출 문자는 **1바이트 코드**(원래 가나 자리, 217칸) → 용량 절약
   - 나머지는 **2바이트 코드**(원래 한자 자리, 1508칸)
   - 합계 **1,725자**까지 수용. 한국어 게임 텍스트에 충분합니다.
2. `_000PRG.DAT` 의 폰트 영역(0x29000~)에 **16×16 1bpp 한글 글리프**를 써 넣음
3. 각 EV 파일의 기록된 오프셋에 번역 바이트를 기록(남는 자리는 0x00 패딩)
4. `build/files/korean.tbl` 에 코드표 저장

출력은 `build/files/` 에 **수정된 파일만** 생깁니다. 원본은 건드리지 않습니다.

## 4. 검증

```bash
python3 tools/verify.py build/files translation/string_map.json translation/script_ko.tsv
```

패치된 파일에서 **다시 읽어** 한국어가 들어갔는지 확인합니다.

## 5. CD 이미지로 되돌리기 (아직 미작성)

`build/files/` 의 파일들을 원본 트랙01의 **원래 LBA 위치에 같은 크기로 덮어쓰면** 됩니다.
파일 크기가 고정 슬롯이고 번역도 슬롯 안에서만 이루어지므로
**ISO 디렉터리 구조를 손댈 필요가 없습니다.** 각 파일의 CD 내 위치는
원본 추출 시 만들어진 `inventory.json`(위치/길이/SHA256)에 들어 있습니다.
— 이 파일이 아직 업로드되지 않았으므로, 이미지 재생성 단계에서 필요합니다.

## 6. 폰트 바꾸기

```bash
KOFONT=/usr/share/fonts/truetype/nanum/NanumGothic.ttf python3 tools/build_patch.py ...
```

16px에서 가독성이 가장 좋은 것은 `NanumGothicCoding.ttf`(기본값)입니다.
픽셀 전용 글꼴(둥근모 등)을 쓰면 더 또렷해집니다.

## 7. 아직 남은 작업

- **메뉴·시스템 텍스트**: `_000PRG.DAT` 안에 Kosinski 압축된 **그래픽 형태**로 들어 있습니다
  (예/아니오, 로드/새게임, 백업램 메뉴 등). 0x3e000 / 0x3e6a0 / 0x424b0 / 0x3fe8e / 0x4025e.
  압축 해제 → 타일 수정 → 재압축 + 타일맵 조정이 필요합니다. 표준 Kosinski라 도구가 많습니다.
- **아이템·기술·몬스터 이름**: EV 파일이 아닌 다른 파일에 있을 가능성이 높습니다.
  `_000PRG.DAT` 와 `SMON*`/`BNK*` 를 같은 방식(포인터테이블+문자표)으로 재탐색해야 합니다.
- **문자열 이동**: 바이트 한도를 넘는 대사를 살리려면 텍스트 블록 뒤 여유 공간으로 옮기고
  포인터 테이블과 **텍스트 opcode 안의 오프셋 참조**(0x06/0x12/0x13 등)를 함께 갱신해야 합니다.
  (현재는 한도 내로 줄이는 방식으로 우회)
- **에뮬레이터 실전 검증** (BlastEm 등)

## 8. 꼭 알아야 할 제약 — 부분 패치는 배포용이 아닙니다

한글 글리프는 **원래 한자/가나가 쓰던 글리프 칸을 덮어쓰기** 때문에,
아직 번역하지 않은 대사는 **일본어가 아니라 깨진 한글로 보입니다.**

- 폰트 칸은 총 1,725개, 일본어가 쓰던 칸이 약 1,750개 → **둘을 공존시킬 수 없습니다.**
- 따라서 중간 산출물은 **작동 확인용**이며, 배포하려면 전량 번역이 필요합니다.
- 번역을 멈춘 상태로 플레이해 보고 싶다면, 그건 정상입니다. 버그가 아닙니다.

## 9. 바이트 한도가 빡빡할 때

번역이 늘수록 쓰는 문자 종류가 늘고, 1바이트 자리(217칸)를 넘긴 문자는
2바이트가 되어 같은 문장이라도 바이트가 늘어납니다.
**전에 들어가던 문장이 나중에 초과로 바뀔 수 있습니다.** 정상 동작입니다.

대응 순서:
1. 표현을 줄인다 (가장 간단. 지금까지는 전부 이 방법으로 해결)
2. 그래도 안 되면 **여유 공간으로 이전**한다 ← 아직 미구현

### 여유 공간 이전 (다음 큰 과제)

각 EV 파일은 128KB 고정 슬롯인데 텍스트 블록은 대략 `0x14800~0x19500` 만 씁니다.
**파일 끝까지 약 27KB가 0xFF로 비어 있습니다.** 여기로 긴 문자열을 옮기면
길이 제약이 사실상 사라집니다.

구현 시 반드시 함께 갱신해야 하는 것:
1. `0x14808` 의 **포인터 테이블** 항목
2. **텍스트 opcode 안의 오프셋 참조** — `0x06`, `0x12`, `0x13`, `0x24` 등
   (`samples/` 가 아니라 선행 연구의 `opcodes.yml` / `readopcodes.c` 참고)

opcode별 오프셋 위치를 먼저 전수 조사해야 안전합니다. 이것이 미완성이라
현재는 "한도 내로 줄이기"로 우회하고 있습니다.
