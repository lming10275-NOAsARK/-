## 이어서 할 일 — 가장 효율적인 순서

### 1) 조각 번역 루프 (강력 추천)

이 게임 대사는 제어코드로 끊긴 **문장 조각**의 조합이고 같은 조각이 수십 번
재등장합니다. 통째로 번역하는 것보다 **조각을 번역해 자동 조립**하는 쪽이
압도적으로 빠릅니다. 실제로 이 세션 번역의 대부분이 이 방식으로 들어갔습니다.

```bash
cd 3x3eyes_kr

# (1) 지금 자동 완성을 막고 있는 조각을 빈도순으로 뽑는다
python3 tools/tm.py translation/script_ko.tsv report 130

# (2) 출력된 '빈도|일본어' 를 보고 translation/glossary.tsv 에 추가
#     형식:  일본어조각<탭>한국어
#     (이미 1,500개 넘게 들어 있으니 말투·호칭을 참고해서 맞추세요)

# (3) 자동 완성
python3 tools/tm.py translation/script_ko.tsv
```

(1)~(3)을 반복합니다. 한 라운드(조각 110~130개)에 **50~220건**이 자동 완성됩니다.

### 2) 패치 만들고 확인

```bash
python3 tools/build_patch.py ext/files translation/script_ko.tsv \
        translation/string_map.json build/files
python3 tools/verify.py build/files translation/string_map.json translation/script_ko.tsv
```

바이트 한도를 넘은 항목은 `translation/overflow_report.tsv` 에 남습니다.
자동 축약된 것도 전부 기록되니 나중에 다듬으세요.

### 3) 긴 항목 직접 번역

조각 루프로 안 되는 긴 항목은 `script_ko.tsv` 에서 직접 번역합니다.
`사용횟수` 가 큰 것부터 하세요.

## 번역 규칙 요약

1. **제어코드는 그대로 유지** — `<br />` `<0xdb>` `<0xdb00>` `<return_p>` `<arrow>`
   `<speak>` `</speak>` `<portrait_NN>` `<wait_NN>` `<E7FC>` `<E7FD>` `[player]`
2. 한 줄 **14~16자** 이내, 한 화면 4줄. 길면 `<br />` 로 끊기
3. **일본어(가나·한자)를 번역문에 남기지 말 것** — 한글 글리프로 덮여 깨집니다
4. `¨` `♥` `～` 등 기호는 자유롭게 사용 가능 (글리프가 새로 생성됨)
5. 번역문 길이는 **원문 글자 수 이하**를 목표로 (바이트 한도 때문)

## 남은 큰 과제

1. **바이트 한도 해소 (여유 공간 이전)** — 미구현
   각 EV 파일은 128KB인데 텍스트 블록은 `0x14800~0x19500` 만 씁니다.
   **파일 끝까지 약 27KB가 비어 있습니다.** 여기로 옮기면 길이 제약이 사라집니다.
   - 이 세션에서 확인한 핵심 사실: **텍스트 데이터는 opcode의 2바이트 오프셋으로 참조**됩니다
     (`0x24`=출력, `0x06`=플래그 참이면 해당 오프셋 처리, `0x12`/`0x13` 등).
   - 따라서 이전하려면 ①`0x14808` 포인터 테이블 ②opcode 안의 오프셋 참조를
     **둘 다** 갱신해야 합니다. 선행 연구의 `opcodes.yml` / `readopcodes.c` 를 보고
     어느 opcode의 몇 번째 바이트가 오프셋인지 전수 조사부터 하세요.
2. **메뉴·시스템 텍스트** — `_000PRG.DAT` 안에 Kosinski 압축 **그래픽**으로 존재
   (0x3e000 / 0x3e6a0 / 0x424b0 / 0x3fe8e / 0x4025e). 압축 해제 → 타일 수정 →
   재압축 + 타일맵 조정. 표준 Kosinski라 공개 도구가 많습니다.
3. **아이템·기술·몬스터 이름** — EV 파일 밖에 있을 가능성. `_000PRG.DAT` 와
   `SMON*` / `BNK*` 를 같은 방식(포인터테이블 + 문자표)으로 재탐색 필요.
4. **CD 이미지 재생성** — `build/files/` 를 원본 트랙01의 원래 LBA에 같은 크기로
   덮어쓰면 됩니다(고정 슬롯이라 ISO 구조 수정 불필요). 각 파일의 CD 내 위치는
   원본 추출 시 만들어진 **`inventory.json`** 에 있는데, **아직 업로드되지 않았습니다.**
   이미지 단계에서 이 파일이 필요합니다.
5. **에뮬레이터 실전 검증** (BlastEm 등)

## 안전장치 (중요)

`build_patch.py` 는 **텍스트 opcode가 있는 엔트리 진입점 3,780곳을 절대 건드리지 않습니다.**
런 추출기가 드물게 opcode 바이트를 문자로 흡수하는데, 거기에 쓰면 대사 분기가 깨집니다.
차단된 지점은 빌드 때마다 보고되니, 그 항목은 번역에서 제외하거나
나중에 opcode 분석을 끝낸 뒤 처리하세요.

또한 `0x00` 은 이 게임의 **문자열 종결자**입니다(실측 확인). 짧은 번역문 뒤를
0x00 으로 채우는 현재 방식은 안전합니다.

## 꼭 기억할 제약

폰트 칸 1,725개를 일본어가 거의 다 쓰고 있어 **한글과 일본어는 공존할 수 없습니다.**
→ 미번역 대사는 깨진 한글로 보입니다. **전량 번역해야 배포 가능**합니다.
